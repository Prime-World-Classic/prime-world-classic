# dds_inventory

Инвентаризация DDS-контейнеров в `pw/branches/r1117/Data/` — нужна, чтобы
убирать D3DX-загрузчик текстур, а не гадать, какие форматы встречаются.

```sh
cd pw/branches/r1117
python3 ../../../tools/dds_inventory/dds_inventory.py Data
```

Выводит: разбор форматов (fourCC / битовые маски / DX10-DXGI), отдельно 2D и
кубы, распределение по числу mipmap-уровней, и **расхождения размера битовых
данных** — сколько байт ожидает загрузчик (`GetSurfaceInfo` из
`Src/Render/ReadDDS.cpp`: DXT блоками 8/16 байт, несжатые — pitch, кратный
4 байтам) против фактического размера файла. Расхождение = файл, который
свой загрузчик не прочитает корректно.

Снимок на 2026-10-13 (`Data/`, 8031 файла):

| вид | формат | файлов |
|---|---|---|
| 2D | A8R8G8B8 (маски 0xff000000/0x00ff0000/0x0000ff00/0x000000ff) | 3715 |
| 2D | DXT5 | 3001 |
| 2D | DXT1 | 1294 |
| 2D | L8 (DDPF_LUMINANCE, 8 бит) | 5 |
| cube | DXT1 | 13 |
| cube | A8R8G8B8 | 3 |

Расхождение размера — 1 файл: `Data/Heroes/Gunslinger/S2/_.dds` (DXT5
1024×1024, объявлено 11 mipmap, а данных ровно на один уровень). В
`Src/System/FileSystem/processing_filelists/files.list` его нет — то есть в
контент он не уходит, это репозиторный мусор.

DX10-заголовков, объёмных текстур и прочих форматов в контенте нет; в
манифесте обновлений (`files.list`) из картинок только `.dds` (4318 записей).
