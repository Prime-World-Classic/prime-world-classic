# render_shot

Визуальный гейт рендер-этапов плана NVRHI (`docs/PLAN_NVRHI.md` §2.8).

Логи и дампы не показывают, что картинка поехала: неверный порядок аргументов
draw, неверный вьюпорт или подставленный шейдер молча рисуют мусор, а E2E при
этом зелёный. Отсюда — сравнение кадров, снятых с ВМС по VNC.

Кадр снимает существующий инструмент (не дублируем):

```sh
python3 /home/rekon/PW/vm7/vncshot.py 127.0.0.1 5918 /tmp/shot.ppm
```

Дальше этот инструмент:

```sh
python3 ppm_tools.py diff /tmp/shot.ppm /tmp/ref.ppm [--tol 8] [--limit 0]
python3 ppm_tools.py png  /tmp/shot.ppm /tmp/shot.png    # посмотреть глазами
```

`diff` печатает долю отличающихся пикселей (порог `--tol` на канал), максимум
дельты и координаты первого отличия; код выхода ненулевой, если доля выше
`--limit`. `--limit 0` уместен только для сравнения «до/после» в один и тот же
момент прогона: кадр боя не детерминирован (таймер, позиция юнита, партиклы).

Процедура и тайминги — скил `.pi/skills/pw-client`, «Скриншот-гейт рендера».

## Основной путь с 2026-10-15: снимок самого клиента + `shot_diff.py`

VNC-кадр — это экран: на нём оверлеи ОС («Activate Windows», часы) и чужие
окна, разрешение не родное. Надёжнее читать бэк-буфер изнутри процесса:
`setvar auto_screenshot 3000` в `C:\pw64\Game\Profiles\autoexec.cfg` → на
кадрах 3000 и 3100 пишутся `pw_auto_{bb,scene,crop}_<N>.png` в cwd процесса
(`C:\pw64\Game\Bin`). Проверено: `scene` == `bb`, `crop` совпадает с
`bb[W-200:H-200]` пиксель-в-пиксель, VNC-оверлеев в них нет.

```sh
python3 shot_diff.py refs/stage2-2026-10-15/pw_auto_bb_3000.png /tmp/new/pw_auto_bb_3000.png --grid
```

Метрика — поканальная дельта; `diff` (порог 8) и `gross` (порог 64). Полоса
шума между двумя прогонами ОДНОГО бинарника на WARP (замеры 2026-10-14/15):
`diff` 4–7%, **`gross` 0,13–0,35%** — держаться внутри неё, иначе это регресс.
Внутри одного прогона (`bb_3000` против `bb_3100`) `gross` доходит до ~2% —
это анимация сцены; этот тест служит только проверкой, что буфер не залипший.
`--grid` печатает счётчики грубых по сетке 16×12: регресс выглядит ПОЛОСОЙ
(один ряд/колонка держает половину грубых), анимация — кластером в сцене.

`refs/stage2-2026-10-15/` — зафиксированный в ветке эталон конца этапа 2
(E2E-прогон `2026.10.15-04.36.54`, карта `Maps/Multiplayer/MOBA/_.ADMPDSCR.xdb`,
1024×768): `pw_auto_bb_3000.png` (весь бэк-буфер) и `pw_auto_crop_3000.png`
(кроп за границу кадра — ловит неверный readback-регион). Каждый рендер-этап,
меняющий картинку осознанно, обязан принести новый эталон и записать в
`docs/PLAN_NVRHI.md`, чем именно он отличается.
