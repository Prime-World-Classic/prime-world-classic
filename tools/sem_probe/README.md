# sem_probe — семантика индекса экземпляра в двух целях компиляции

Проба для шага 9 и шага 11 очереди этапа 3 (`docs/PLAN_NVRHI.md` §2.10 «шаг 2»,
§3.z п.4–п.5). Отвечает на вопрос, **можно ли держать один исходник шейдера и
выбирать форму индекса экземпляра в драйвере компиляции**, не генерируя текст.

## Запуск

```sh
tools/sem_probe/sem_probe.sh [фильтр-подстрока цели]   # dxbc | spirv
```

Компилятор — вендоринговый DXC (`tools/spirv_probe/vendor/dxc/bin/dxc`, этап 1).
`vs_3_0` этой пробой не проверяется: DXC не поддерживает SM3, а в D3D9 индекс
экземпляра и не бывает системной семантикой — там он поток вершин
(`BLENDINDICES0` с дивизором), его синтезует `D3D9Backend` (шаг 9).

## Результат (2026-10-15, DXC из вендоринга этапа 1)

| режим | объявление | DXBC (`-T vs_5_0`) | SPIR-V (`-spirv -T vs_6_0`) |
|---|---|---|---|
| 0 | `int inst : BLENDINDICES0` (как сейчас в D3D9) | OK | OK |
| 1 | `int inst : SV_InstanceID` | **FAIL** `error: SV_InstanceID must be uint.` | OK |
| 2 | `int inst : INSTANCE_INDEX_SEM` (макрос в позиции семантики) | **FAIL** та же ошибка (макрос раскрылся) | OK |
| 3 | `int inst : V_SV_InstanceID` (выдуманная семантика) | OK (!) | OK |
| 4 | `int inst : TEXCOORD15` | OK | OK |
| 5 | `uint inst : SV_InstanceID` | OK | OK |
| 6 | `uint inst : BLENDINDICES0` | OK | OK |
| 7 | макрос на всё объявление (`uint inst : SV_InstanceID`) | OK | OK |
| 8 | макрос на всё объявление (`int inst : BLENDINDICES0`) | OK | OK |
| 9 | макрос объявления не определён | FAIL `HLSL requires a type specifier` | FAIL |
| 9d | макрос объявления приходит от драйвера: `-D "INSTANCE_INDEX_DECL=uint inst : SV_InstanceID"` | OK | OK |

Декодирование SPIR-V (режим 1 в `uint`-варианте): единственный
`OpDecorate … BuiltIn` — `InstanceIndex` (43).

## Выводы

1. **Тип обязан быть `uint`.** С `int` DXBC-путь падает
   (`SV_InstanceID must be uint.`), а SPIR-V-путь компилируется молча — то есть
   расхождение двух целей не видно на одной цели. Драйвер компиляции (шаг 11)
   обязан выдавать ровно `uint inst : SV_InstanceID`.
2. **Макрос раскрывается и в позиции семантики (режим 2), и во всём объявлении
   (7, 8), и если объявление передаёт драйвер через `-D` (9d).** Значит форма
   индекса экземпляра выбирается на входе компиляции без правки `.hlsl` и без
   генерации текста шейдера — как и предполагает §3.z п.4 (прослойка SM3→SM6
   как шаг драйвера).
3. **Опечатка в системной семантике не ловится:** `V_SV_InstanceID` (режим 3)
   компилируется в обеих целях как обычный вход потока вершин. Проверять надо
   декодированием SPIR-V (наличие `BuiltIn InstanceIndex`) — так же, как это
   делает `sem_probe.sh` в конце.
4. **DXC не даёт настоящего SM5 DXBC:** `-T vs_5_0` сопровождается
   `warning: Promoting older shader model profile to 6.0 version`. Для DX12-пути
   это либо SM6 DXBC, либо `fxc` (в вендоринге его нет). Отметить в §3.z п.4.
5. **В Vulkan-цели индекс экземпляра перестаёт быть входом потока вершин**
   (`BuiltIn InstanceIndex`), т.е. раскладка вершин в макете §3.z п.1 не несёт
   атрибута экземпляра; в D3D9-контуре он остаётся атрибутом потока с
   дивизором (режим 0/6) — ровно то, что разводит `D3D9Backend` и будущий
   `NvrhiBackend`.
