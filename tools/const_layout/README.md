# const_layout — раскладка константных регистров по `GlobalMasks.h`

`python3 const_layout.py [путь/к/GlobalMasks.h]` (по умолчанию —
`pw/branches/r1117/Src/Render/GlobalMasks.h`).

Печатает для VS и PS: названные регистры (`#define <ИМЯ>  cN` и
`<ИМЯ>_BEGIN/END`-пары), пересечения диапазонов и покрытие.

Знаки в колонке диапазона: без знака — размер задан явным `_END` или
массивом (`BEGIN + N`); `~` — размер выведен из расстояния до следующего
имени, на него нельзя опираться (последний регистр секции «дотягивается»
до c255).

Зачем. Этап 3 требует описать раскладку uniform-буфера (`cb0` в SPIR-V) и
положить её в фиксированный дескрипторный макет. Инструмент отвечает на три
вопроса:

* какие имена вообще есть и какие диапазоны они накрывают
  (явными размерами покрыто 8/256 регистров — этого мало, значит
  авторитетный источник раскладки — reflection из DXC, а заголовок даёт
  только имена);
* где один и тот же регистр значится под разными именами (пересечения) —
  это места, где раскладка зависит от семейства материалов
  (терраин/вода/точечные источники делят c10..c15, `SAMPLER*_MUL/ADD`
  делят c20..c27 с `PSHADER_LOCALCONST*`);
* какие регистры вообще не названы (дыры) — их не должен занимать
  генерируемый макет.

Живой диапазон и «сколько регистов реально меняется» меряются не здесь, а
счётчиками `ConstStore` в инструментальной сборке клиента
(`-DPW_RENDER_SHADER_STATS`, dev-var `verify_const_block`) — см. §2.9 плана.
